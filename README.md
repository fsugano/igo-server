# 囲碁対局場

パンダネット・東洋囲碁・野狐囲碁のようなオンライン囲碁対局サービスの MVP です。

## できること

- アカウント登録・ログイン（自己申告の棋力から初期レーティングを設定）
- ロビー：対局の募集・受諾、対局中の一覧、オンラインユーザー一覧
- 9 / 13 / 19 路の対局（置き碁 2〜9 子、コミ自由、日本ルール / 中国ルール）
- 石の取り上げ、コウ、自殺手禁止、パス、投了
- 二連続パスで整地へ：死に石をクリックで指定し、双方が合意すると終局
- 持ち時間：日本式秒読み / フィッシャー。時間はサーバー側で管理し、時間切れは自動で負け
- 観戦、対局チャット、着手音
- 棋譜：SGF ダウンロード、終局後の棋譜再生（← → キー対応）
- レーティング（Elo 方式、100 点 = 1 段級）とプロフィールの対局履歴
- 対局モードの切り替え：人対人（募集・受諾）／人対AI／AI対AI（観戦）。AI との対局はレーティングに影響しません
- 観戦者向けの形勢ゲージ（対局者には表示しない）、運営向けの動画収録モード
- 観戦者向けの音声実況（日本語・英語。1手ごとに読み上げ）
- プロフィールの戦績（黒番・白番・対人・対AI・盤の大きさ別の勝敗、勝ち方、連勝、レーティングの推移、よく打つ相手）と棋風判定（実利派・厚み派・戦闘派・バランス型。5局以上で判定）

## AI（コンピューター）

ロビーの「対局を始める」で **人対AI** か **AI対AI** を選ぶと、すぐに対局が始まります。AI 同士の対局はロビーの「対局中」から誰でも観戦できます（1 人 1 局、全体で 4 局まで）。

- **内蔵 AI**（追加インストール不要）：モンテカルロ探索（ランダム対局 + AMAF）。入門 Lv1 / 初級 Lv2 / 中級 Lv3 の 3 段階で、強さは 1 手あたりの読みの量の違いです。9 路で遊ぶのが一番楽しめます。19 路では弱めです。
- AI はアカウント（`AI-Lv1` など）として対局に参加します。名前に `-` が入るので人のアカウントと重なりません。ログインはできません。
- 二連続パスのあとは AI が死に石を指定して合意します。人が死に石を直すと、AI はそのまま合意し直します。
- 対局中にサーバーを再起動しても、AI の手番から続きを打ちます。

### AIとのチャット

人対AIの対局では、チャット欄でAIに話しかけられます。AIは対局の始めに挨拶し、終局後にお礼を言います。

- **APIキーなし**：決まった台詞で返事をします。費用はかかりません
- **APIキーあり**：Claude（Anthropic の言語AI）が盤面と形勢を見ながら会話します。話しかけた言語で返事をします。リポジトリ直下に `.env` を作り、キーを書いてからサーバーを起動してください（`.env` は Git に含まれません）

```
ANTHROPIC_API_KEY=sk-ant-...
# 任意：使うモデル（既定は claude-opus-5-5。claude-haiku-5-5 にするとかなり安くなります）
AI_CHAT_MODEL=claude-haiku-5-5
# 任意：1局あたりのAIの返事の上限（既定 30）
AI_CHAT_MAX_PER_GAME=30
```

APIキーは [Claude Console](https://console.anthropic.com/) で作れます。利用料は前払いのクレジットから使った分だけ差し引かれます。Claude.ai の有料プランとは別です。サーバー起動時のログに `AI chat: Claude API` と出ていれば、キーが読み込まれています。

### KataGo など外部エンジンをつなぐ

GTP（Go Text Protocol）に対応したエンジンなら、設定を JSON で書くだけで AI の選択肢に加わります。例：KataGo を Windows で使う場合、`ai-engines.json` を作って

```json
[
  {
    "id": "katago",
    "name": "KataGo",
    "label": "KataGo（最強）",
    "rank": "9d",
    "command": "C:/katago/katago.exe",
    "args": ["gtp", "-model", "C:/katago/model.bin.gz", "-config", "C:/katago/gtp_example.cfg"]
  }
]
```

`.env` に `AI_GTP_ENGINES` としてそのファイルの場所（または JSON そのもの）を書いてから起動します。

```
AI_GTP_ENGINES=C:/Users/PC/Desktop/ai-site/igo-server/ai-engines.json
```

- `name` は英数字と `_`（アカウント名は `AI-KataGo` になります）、`rank` は表示用の棋力（`9d`、`5k` など）
- 1 手あたりの考える時間は KataGo の設定ファイル（`maxVisits` や `maxTime`）で調整します
- 新しいエンジンの組み込み方：`apps/server/src/ai/engine.ts` の `Engine` を実装して `apps/server/src/ai/index.ts` の `loadEngines` に加えます

## 運営メニュー・形勢ゲージ・動画の収録

### 運営の権限を付ける

運営メニューは、権限のあるアカウントだけが使えます。アカウントを登録してから、サーバーのある環境で次を実行します。

```bash
npm run set-role -w @igo/server -- <ユーザー名> admin
```

権限は `admin`（設定を変えられる）、`staff`（収録担当。設定は見るだけ）、`user`（一般）の3つです。ログインし直すと、画面上部に「運営」が出ます。

### 形勢ゲージ

- 観戦している人には、盤面の横に形勢ゲージ（黒の勝率）を表示します。内蔵 AI による速い解析なので、目安です。
- **対局者本人には表示しません**（サーバーも送りません）。AI の助言を受けながら打てないようにするためです。
- 人が打つ対局では、観戦者に見せる形勢を**数手前の局面**にします（既定 3手）。対局者が別の端末で観戦画面を開いても、今の局面の助言にならないようにするためです。AI 同士の対局は遅れなしです。
- 遅れの手数は、運営メニュー（`/admin`）の「運営設定」で 1〜10手の間で変えられます。変えるとすぐ観戦画面に反映されます。

### 動画の収録（YouTube 投稿用）

1. 運営メニュー（`/admin`）の「収録できる対局」から「収録モードで開く」を選びます。16:9 の動画用の画面になります。
2. 上の帯で画質（1080p / 720p、60fps / 30fps）と、形勢ゲージの有無を選びます。設定は URL に残るので、同じ見た目で何度でも収録できます。
3. 「● 収録開始」を押し、共有する画面に「このタブ」を選びます。開始の演出（対局者の紹介）から収録されます。
4. 「■ 収録停止」を押すと、動画ファイル（WebM）が保存されます。そのまま YouTube に投稿できます。

- OBS などの別のソフトは不要です。ブラウザの標準機能だけで収録します。パソコン版の最新の Chrome か Edge を使ってください。Chrome・Edge では盤面の範囲（16:9 の部分）だけが収録され、上の帯は映りません。
- 1080p で収録するには、ブラウザのウィンドウを十分に大きくしてください（小さいと画面に警告が出ます）。
- 対局者がプロフィール画面で「動画での公開」を許可していない場合、名前は「黒」「白」と表示されます。
- 収録の方式は運営設定で選びます。今使えるのは「A. タブの収録」です。「B. 描画を直接収録」「C. 高速書き出し」は準備中です。
- 保存される WebM には動画の長さの情報が入らないため、一部の再生ソフトでは早送りができないことがあります。

### 音声実況（ナレーション）

- 観戦画面の「音声実況」で **日本語** か **English** を選ぶと、1手ごとに読み上げます。選んだ言語はブラウザに記憶されます。収録モードでは上の帯で選びます（URL の `narr=ja` / `narr=en`）。
- 読み上げる内容：手番と手数、場所（「右上の星」「左辺」など）と座標、石を取ったとき、アタリ、コウ、パス、整地、結果。日本語の座標は「16の四」（横は左から数字、縦は上から漢数字）の形で読みます。
- 形勢ゲージが出ているときは、形勢が大きく動いたときと20手ごとに、「○手目の時点の形勢」として読み上げます。人が打つ対局では、ゲージと同じく数手遅れの局面です。
- **対局者本人には実況しません。** アタリなどを知らせると助言になるためです。
- 音声はブラウザの標準機能（Web Speech API）で作るので、費用はかかりません。声の種類はパソコンに入っている音声によります（Chrome の「Google 日本語」などがあれば、それを使います）。
- 打つのが読み上げより速いとき（AI どうしの対局など）は、読み切れなかった手を飛ばして、最新の手を読みます。
- ページを開いてすぐは音声が出ないことがあります（ブラウザの決まりで、一度画面を操作するまで音を出せないため）。その場合は画面を一度クリックしてください。
- 収録した動画に実況の声が入るかは、ブラウザと音声の種類によります。入らない場合は、今後の改善（サーバー側で音声を作って動画に重ねる方式）で対応します。

## 構成

| 場所 | 中身 |
| --- | --- |
| `packages/shared` | 囲碁ルールエンジン（盤・コウ・整地）、持ち時間、SGF、レーティング、通信の型。サーバーとブラウザで共通 |
| `apps/server` | Fastify（REST API）+ Socket.IO（リアルタイム対局）+ PostgreSQL。`src/ai` に AI エンジン |
| `apps/web` | React + Vite の画面 |

対局中の状態はサーバーのメモリにあり、一手ごとに PostgreSQL へ保存します。サーバーを再起動しても対局中の碁は復元されます。

## 開発環境で動かす

必要なもの：Node.js 22、PostgreSQL 16

```bash
npm install
createdb igo            # DATABASE_URL の既定値は postgres://postgres:postgres@localhost:5432/igo
npm run migrate
npm run dev             # API: http://127.0.0.1:3000 / 画面: http://localhost:5173
```

サーバーは既定で 127.0.0.1 だけで待ち受けるので、ほかのPCからは接続できません（Docker イメージでは 0.0.0.0）。

PostgreSQL をインストールしていない場合は、Docker で起動できます。

```bash
docker run -d --name igo-db -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=igo -p 127.0.0.1:5432:5432 postgres:16
```

Windows の PowerShell で「スクリプトの実行が無効」と出る場合は、`npm` の代わりに `npm.cmd` を使うか、コマンドプロンプトで実行してください。

テスト（`igo_test` データベースを使います。中身は毎回消去されます）：

```bash
createdb igo_test
npm test
```

## 本番用に動かす

```bash
docker compose up --build   # http://localhost:3000
```

単体のコンテナとして Fly.io、Render、Google Cloud Run、AWS ECS などに載せられます。環境変数は `DATABASE_URL`（本番では必須）、`PORT`、`NODE_ENV=production`（HTTPS 必須。Cookie が Secure になります）です。

- `TRUST_PROXY`：リバースプロキシやロードバランサーの後ろで動かすときに設定します。Fly.io・Render・Cloud Run のようにプロキシが1段なら `1`、プロキシの IP が決まっていればその IP（CIDR 可、カンマ区切り）。**未設定ならどのプロキシも信用しません**（`X-Forwarded-For` を偽装して、ログイン・登録の回数制限をすり抜けられないようにするため）
- `ALLOWED_ORIGINS`：Web 画面を API と別のドメインで配信するときに、そのドメインを書きます（例：`https://igo.example.com`）。未設定なら、同じサイトからのリアルタイム接続だけを受け付けます

- メール認証、パスワード再設定、利用規約・プライバシーポリシー

- **プレミアム会員（月額）**：AI による対局後の検討・形勢グラフ、棋譜の無制限保存、広告なし、プロフィールの装飾
